## Задача и результат

Я разработал REST-сервис технической поддержки на Java и Kotlin. Сотрудник создаёт заявку, меняет приоритет и срок, ведёт её до решения или отмены. Руководитель получает статистику по периоду. Работа заняла **72 академических часа**. План по направлениям приведён в [backlog](backlog.md). Отдельный фактический хронометраж по этапам не приводится.

Подготовлены [12 пользовательских историй](user-stories.md), [архитектура](architecture.md), [модель данных](data-model.md), [контракт OpenAPI](openapi.yaml), [коллекция запросов](postman/support-service.postman_collection.json) и [тест-план](test-plan.md). Код организован по предметным модулям и слоям. Flyway создаёт схему и справочник категорий. PostgreSQL сохраняет данные в именованном томе.

## Решения на Kotlin

Java-компонент ReportDataSource читает одну выборку заявок по периоду создания [from, to). SummaryReportService рассчитывает показатели этой выборки. Nullable-поле среднего времени решения различает отсутствие решённых заявок и нулевую длительность. При расчёте длительности Kotlin использует filter и fold по коллекции решённых заявок, складывает секунды с дробной частью и делит сумму с округлением лишь в конце. Время проверки просрочки задаёт Clock.

## Демонстрация и сохранность данных

На версии A создана заявка `0563375f-204f-4699-8318-5f4af6daa1e6`, ответ 201. Два PATCH перевели её в IN_PROGRESS и RESOLVED, оба с кодом 200. Попытка вернуть закрытую заявку в работу дала 409 и `STATE_CONFLICT`. После отказа карточка и обе записи истории совпали с исходными. Отчёт после создания показал 1 заявок, решённых: 1.

## Эксплуатация и ограничения

В [проверке восстановления БД](database-backup.md) архив развёрнут в отдельную базу и сравнены данные. [Инструкция диагностики](runtime-diagnostics.md) рассматривает недоступный PostgreSQL, провал readiness и ошибку Flyway. При отказе сначала проверяю состояние контейнеров и логи, затем выбираю восстановление сервиса, БД или совместимого образа.

Приложение доступно через loopback на стенде. Для работы runner нужны включённые Windows и WSL. В API нет аутентификации и разделения ролей. Повторный POST после сетевого сбоя может создать вторую заявку. При несовместимом изменении схемы одного возврата образа недостаточно. Репозиторий приватный; для просмотра запусков преподавателю нужен доступ.

# Возврат к предыдущему релизу

Горохов Георгий, 4П1.23

Перед откатом нужны две успешно доставленные версии и совместимая схема PostgreSQL. Сведения о них находятся в /srv/support-service/current.json и previous.json. Предыдущий образ и оба комплекта Compose-файлов должны оставаться на стенде.

В Linux от пользователя runner, из корня checkout актуальной версии:

```bash
python3 -B scripts/staging/rollback.py
curl --fail http://127.0.0.1:18080/actuator/health/readiness
```

Скрипт блокирует параллельную доставку, берёт сохранённый Compose и локальный образ предыдущего релиза. Имя проекта и том БД сохраняются. После запуска проверяются ID контейнерного образа и ответы API. Переход записывается в rollback.json. Для проверки данных до и после отката сравниваются карточка одной заявки и её история. Если образ удалён, перед повторным запуском требуется загрузить его из GHCR по сохранённому digest. При отказе после смены контейнера проверить фактический статус через docker compose ps и логи приложения.
